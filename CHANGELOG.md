### Security disclosures and known limitations

- Beta-0.1 is **not end-to-end encrypted**. The server processes text plaintext; storage envelopes are not E2EE. Calls media is WebRTC hop encryption only, with the SFU inside the media trust boundary — not audited E2EE.
- No production-scale database, multi-region/high-availability topology, measured SLO or completed DR.
- No public passkey signup/signin/bootstrap, authenticator-management HTTP/UX, recovery, user-facing step-up or independent security notifications. Separate internal add-authenticator/management, sign-in and signup seams are disabled by default and forbidden in production; all keep the public capability false and are not usable public authentication features. Authenticated QR device linking has server-side slices (challenge/approve/SAS/step-up/redemption); its client UX, account-recovery flow and device-compromise story remain open.
- Account data export and account deletion/retention are implemented as authenticated HTTP routes with a background sweeper, and the iPhone now ships account-data UI (export request/verified download, deletion schedule/cancel with the server role-enforced 7-day grace and typed confirmation). They are not a production data-deletion certification and have not been run at production scale. Contact upload remains deliberately absent.
- First-request media/link fetching is disabled; there is no malware scanning/transcoding production pipeline, push, public Spaces or moderation case workflow.
- Calls exist only as an unreviewed preview: server signaling plus a join-grant endpoint behind the configured media plane, an iPhone call surface (history/log/voice session) and a web signalling UI plus fallback page. There is no push ringing, CallKit, video/screen share, production SFU/TURN capacity evidence or independent call-security review. The isolated call-control package, loopback SFU/TURN harness and local `start.bat` media stack are not production availability.
- No full production-ready iPhone/Web/Android/macOS/Windows/Linux client; Apple has only the thin connected harness described above, the Web surface is a public site plus a developer-preview `/app` client, and remaining interaction states can otherwise be synthetic and are labelled demo/roadmap. The `/app` client has no server-synced drafts/folders, no PWA/push/offline cache, no video/screen-share calls, its call media stays unavailable unless the server advertises a media plane, and its browser E2E is a committed GitHub Actions gate (16/16 checks) while hosted deployment headers/CSP, a WCAG audit and the refresh-token storage policy are still release gates.
- No public signed native download artifacts, installable PWA or production release automation; the public site's download cards are "Coming Soon" placeholders.
- E2EE, production calls, media processing and production operations require their separate implementation, interoperability, security, accessibility, load and audit gates.

### Compatibility

- Realtime protocol `1` remains the strict messaging stream; additive identity/access events use protocol `2`.
- Node runtime requirement is 22+.
- Apple foundation declares iOS 18/macOS 15 and Xcode 26 project generation.
- Android foundation declares minimum SDK 26, target/compile SDK 36 and JDK 17.

Internal roadmap phase names are not versions; the sole public release label remains Beta-0.1.
